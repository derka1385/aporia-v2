# APORIA — explicit-state research laboratory

## Scope (5 October 2026)
The initial checkout contained only Git metadata. The current local implementation includes an approved APORIA landing identity and an inspectable research laboratory. This delivery upgrades the controller to `aporia-research-v3` and preserves existing records and brand assets. The supplied advanced architecture brief governs functionality; the visual brief governs the landing composition. Node 26, npm, Python, Graphify and Ollama are installed. Qwen 2.5 (1.5B, 3B, 3B Q8), Llama 3.2 3B and Nomic embeddings are downloaded. Local inference needs the Ollama service running.

## Components
React/Vite serves the interface. Three.js renders a folded trefoil surface sampled with thousands of GPU points. A Node server owns research sessions, tools and SQLite memory. The client consumes server-sent events; snapshots are persisted after every operation. The server binds only to loopback.

Each profile maintains its own argument graph, confidence history, branch queue, experiments and operation reward estimates. Profiles share only the starting question and an immutable snapshot of memory from *before* the session. Fresh mode uses empty memories and routing rewards; prior mode explicitly includes both. They cannot see one another's work. Graph edges express support, dependency, attack and refinement. LLM text is a structured proposal, never trusted executable code or established evidence.

The controller scores eligible operations and branches using uncertainty, objection pressure, novelty, missing evidence, downstream impact and learned utility. It selects an operation, applies a graph mutation or tool result, recomputes metacognition, records observed information gain, updates operation utility and repeats. Initial hypothesis, assumptions, a generated counterfactual and adversarial testing are coverage requirements; their later ordering is state-based. Stopping needs tested branches and stabilization, or an explicit compute budget.

## Real differentiation
For every numeric knob, policy = common baseline + Δ × (profile target − baseline). Explorer, Formalist, Skeptic, Synthesizer and Minimalist differ in operation weights, visible context, retrieval depth, uncertainty tolerance, branching, adversarial intensity, sampling temperature and stabilization threshold. Tool gates vary above declared Δ thresholds. At Δ=0 policies and seeds are identical. Baseline and prompt-only conditions are available; model condition selects an explicit downloaded model per profile, with its confounds recorded.

## Tools and memory
SQLite persists sessions, node memories, experiment outcomes and per-function rewards. Retrieval uses a clearly labeled token-similarity proxy, scored with memory usefulness; it is not an embedding. Unresolved recalled objections can lower confidence; resolved ones retain their provenance without attacking the hypothesis again. Remembered productive operations warm-start routing only in prior-memory mode. A local curated reading index links to primary philosophical references; it is a bibliography, not live literature search. A finite propositional checker exhaustively evaluates explicit Boolean formulas generated by the model. It tests the formalization only, never validates philosophical truth. Invalid formulas, directly circular premises and inconsistent premises receive no support edge or confidence credit; direct circularity detection is not a general equivalence prover. Counterfactual tests are structured LLM judgments with modest belief updates. Untested hypotheses remain provisional. After revision, coverage is recalculated for the new root ID; testing the former root does not test its replacement.

## Metrics and visual state
Pairwise operation-path similarity, graph branch-set similarity, local-embedding argument/conclusion similarity (token-vector fallback), unique assumptions/objections and explicit stance disagreement are computed from actual profile records. Disagreement excludes undecided positions. Completed runs use local Nomic embeddings; pending or unavailable embedding analysis is explicitly lexical. Embedding distance requires future independent argument-quality validation. Information gain is an operational change-in-state proxy, not Bayesian evidence. Confidence is a controller heuristic, not a calibrated probability. Particle uniforms follow measured curiosity, uncertainty, contradiction, attention, rejection and stabilization; manual modes are explicitly simulation.

## Protocol and durable experiments

`protocol.mjs` fingerprints the engine, provider, policies, tools, store, study implementation and dependency lockfile. The record includes the runtime version and installed model digests/quantizations. SQLite `initial_states` stores immutable pre-session memories/rewards by SHA-256 digest; full JSON exports attach this snapshot. Older records are preserved and labeled legacy when they lack coverage/protocol data. UI state and SSE avoid repeatedly sending the full memory snapshot.

`ResearchDossier.jsx` exposes tests of the current hypothesis, assumption coverage, formal support, pending challenges, open questions and evidence boundaries. `complete` means execution ended, not that every hypothesis survived or every challenge was settled. Failed profiles remain in totals and compute usage, but have no completed-position comparison. Token totals include known usage from failed/repair attempts; unavailable server/network usage cannot be measured. Recorded inference time is the provider's summed generation time, not end-to-end wall time or a GPU benchmark; embedding analysis and UI rendering are outside it.

`study.mjs` creates a new isolated in-memory store per case and writes a case snapshot after every operation. A manifest pins cases, source digest and model identities. Resume skips terminal successes and errors, preserves interrupted snapshots before restart and refuses changed identities. The CLI bounds each invocation and has a process lock. The browser API independently allows one live session at a time; the two entry points do not share a global inference lock and should not be run concurrently.

The controller is a seeded adaptive policy, with bounded coverage/stopping requirements and actual model/tool operations. Policy learning updates heuristics from observed state changes; it is not neural-network training. Δ=0 reuses identical inference requests inside the session and records cache reuse; identical controls are therefore not independent stochastic replications.

## LobBot findings
Inspected local `../LOBBOT/github-publish/{pipeline.py,stages/reap.py,stages/heal.py,stages/bits.py,stages/quantize.py,stages/_util.py,README.md}`. Its default teacher is Qwen3-30B-A3B. REAP scores experts from router weights multiplied by expert-output norm on task calibration tokens, retains higher scores at uniform expert counts per layer, and records per-layer saliency. Healing applies LoRA SFT to teacher answers (optional KL distillation and dense fallback). Quantization uses an importance matrix and per-layer/per-projection expert precision under a size budget, with static attention/embedding/output precision. Evaluation chooses a task-performing candidate; packaging exports GGUF and an Ollama Modelfile. README speed/size figures are project claims, not independently measured here.

This is task-specializing compression, not a personality generator. Different calibration corpora, pruning masks and bit allocations could yield different trajectories, but impairment may masquerade as diversity. Its vLLM/CUDA training pipeline is not a small Mac-local experiment. No VM jobs, pruning or training are launched. Existing Q4/Q8 local variants allow an initial quantization comparison, with quality, size, model identity, seeds and policy condition retained. A future study needs matched checkpoints, several seeds/questions, blind argument evaluation, quality controls and equal token budgets. No scientific claim follows from one run.

## Feasible now vs experimental
Feasible: actual small-model inference; dynamic routing; graph/memory persistence; tools; in-session utility learning; policy differentiation; local rendering and export. Experimental: natural-language adversarial validity, confidence calibration, lexical diversity as semantic diversity, model-level causation, compression as useful cognition. There is no offline canned answer fallback: provider errors remain visible and logged.

## Integrated paper discovery extension (5 October 2026)

The existing stateful cognitive engine now sits inside a complete paper-discovery workflow. `DiscoveryManager` owns one child Python worker per existing APORIA session. The shared active-slot guard covers literature acquisition, cognition, dialectical trials and completion, including concurrent create requests. JSON-line events update the same SQLite record and SSE stream. Pause/resume suspends the worker and coordinates the cognitive controller; stop aborts both, settles cognitive work and releases the slot before responding. Unexpected worker exit cancels orphan cognitive inference. Partial papers, transcripts and failures remain saved.

The worker loads only project-local dependencies and uses a private directory `research/data/jobs/<session-id>/` for immutable request/topic, corpus, raw texts, indexes, graph SQLite, LLM caches, trials and briefs. Public literature requests run through the bounded upstream adapters. Sources are normalized from raw OpenAlex work objects, snapshot before full-text download and update after each attempt. SHA-256 identifies acquired source text. Up to twelve earlier corpora (bounded to 1,200 merged records) expand the current comparison database without importing their PDF paths or changing those records.

Checked source claims reconstruct premise/conclusion argument graphs and a code-verified Boolean skeleton. Claims/abstracts form hybrid BM25/dense indexes using installed Nomic embeddings. A published argument grounds every new cognitive model call; the resulting graph objections are mapped through the strict premise/case validator into real Crux trials. Developing an earlier record instead reuses its saved profiles and preserves their original protocol, model identities and initial memory snapshot in `cognitiveSource`; it does not claim those original profiles were generated from the newly retrieved paper.

The vendored engine retains APORIA generators, hidden-premise/tradition/naive attacks, prior-art restatements, target/duplicate exclusion, adaptive Director queue, two defender exchanges, citation verification, referee decisions, recursive premise repairs and bounded brief selection. Defenders returning invalid structured output cannot manufacture a successful trial. The new completion step automatically grades, revises, regrades and searches prior art for the effective final contribution. Ranking requires both academic assessment and assessed final novelty and uses survival × novelty × mean quality / 5. Original objection novelty and both proposal versions remain separate.

`DiscoveryPanel` is the primary result below the existing observatory. Directions expose theses, counterarguments, replies, source premises/quotes, prior literature, academic criteria and remaining research. Papers, Debates and Research log expose supporting records. The original Laboratory remains in a native disclosure. Individual Markdown and complete JSON exports are tied to the saved session, and cached source reads require a path contained in that job directory. Reflection and earlier archive records remain supported.

The local model adapter does not resolve cloud or subscription providers. Installed-family diversity is recorded explicitly; one-family operation is possible without claiming independent model validation. Corpus coverage and model judgments remain provisional. Upstream identities and modifications are recorded in `research/UPSTREAM.md` and `research/upstream.json`.
